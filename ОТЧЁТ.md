# Отчёт: сайт и логотип ПОПАДОС

## 1. Что сделано

- **Логотип.** Надпись ПОПАДОС, где первая «О» заменена красной фишкой: это отмеченный трек в карточке бинго, «попадание» и виниловая пластинка одновременно. Сделаны версии для светлого, фиолетового и тёмного фона, иконка «П●» для аватарки и вкладки браузера, PNG-иконки и картинка для превью ссылок. Буквы переведены в кривые, поэтому шрифт для логотипа не нужен. Лист логотипа: `docs/logo-sheet.png`, файлы: `assets/img/logo/`.
- **Главная страница:** шапка с меню и кнопкой «Играть» (на телефоне меню-бургер), первый экран с заголовком «Угадай песню. Забери победу.», ближайшая игра (только если она есть в данных), карточки ближайших игр, «Как играть» в 4 шага, «О проекте» с галереей-заглушкой и ссылкой на VK, «Корпоративы» с формой, FAQ, подвал с адресом и ссылкой на карту.
- **Страница «Расписание игр»** (`schedule/`): все опубликованные будущие игры по месяцам, сортировка по дате, прошедшие скрываются автоматически через 3 часа после начала.
- **Данные в JSON** (`data/`): игры, площадка, контакты, Ticketscloud, галерея, FAQ. Инструкция с примерами: `docs/КАК-РЕДАКТИРОВАТЬ.md`.
- **Автопроверка и публикация:** `scripts/check.mjs` ловит ошибки в датах, ценах, ссылках и путях к афишам и пишет их по-русски. GitHub Actions (`.github/workflows/pages.yml`) не опубликует сайт с ошибкой в данных.
- **Без фикций:** расписание пустое (дат и цен вы не давали), вместо игр показывается честное «Новые даты скоро появятся» с кнопкой на билеты Ticketscloud по вашему мета-событию и ссылкой на VK. Форма не имитирует отправку. Контакты и политика показываются, только когда заполнены.
- **Техника:** без библиотек и сборки; шрифты Unbounded и Manrope лежат на сайте (не зависят от Google); семантичная разметка, доступное меню, контраст кнопок по WCAG AA, SEO-заголовки и описания, разметка Schema.org Event для игр, страница 404.

## 2. Что проверено

Проверял в Chromium на локальном сервере, на экранах компьютера (1366 px), iPhone 13 и Pixel 7.

- Меню на телефоне открывается и закрывается, якоря и переход на расписание работают, страница расписания открывается напрямую по адресу.
- На тестовых данных (подставлялись только в браузере, в файлы не попали): прошедшая, скрытая и игра без даты не показываются; игра без названия получает название по умолчанию; игра без ссылки на билеты показывает «Продажа билетов скоро откроется» вместо кнопки; игры сортируются по дате.
- Горизонтальной прокрутки на телефоне нет. Ошибок JavaScript в консоли нет.
- Форма с подключённым тестовым адресом: без имени и контакта не отправляется, без согласия не отправляется, при ответе сервера с ошибкой пишет «Не получилось отправить», «Заявка отправлена» только при успешном ответе.
- `node scripts/check.mjs` проходит; на заведомо неправильных данных находит все 6 ошибок.

## 3. Статус Ticketscloud

**Подключено, но живьём не проверено.** Из среды, где я работал, сайты ticketscloud.com закрыты сетевыми настройками, поэтому открыть окно покупки я не смог.

Что подтверждено по официальному скрипту виджета `ticketscloud.com/static/scripts/widget/tcwidget.js`:
- он открывает оформление окном поверх сайта по атрибутам `data-tc-event`, `data-tc-token`, `data-tc-lang`, а для мета-события добавляется `data-tc-meta="true"`;
- окно загружает `https://ticketscloud.com/v1/widgets/common/meta?meta_event=…&token=…&lang=ru`. Это ровно те три параметра, что вы прислали;
- скрипт ловит нажатия на всей странице, поэтому кнопки, построенные из `events.json`, тоже работают;
- на телефоне открывается то же окно поверх страницы, а не новая вкладка.

**Про токен.** Официальный скрипт сам вставляет токен в адрес окна покупки, который видит каждый посетитель. Значит, это публичный токен виджета, а не секретный API-ключ (в его содержимом только идентификатор, без прав доступа). Поэтому он лежит в `data/site.json`. Страницу справки Ticketscloud об этом токене прочитать не удалось (support.ticketscloud.com не открылся), так что вывод сделан по коду их скрипта. Если хотите полной уверенности, спросите поддержку Ticketscloud: «этот токен из кода виджета можно публиковать на сайте?»

Если скрипт не загрузится (блокировщик рекламы и т. п.), кнопка просто откроет ту же страницу покупки Ticketscloud в новой вкладке.

## 4. Что нужно от вас

1. **Проверить кнопку покупки** после публикации: нажать «Билеты в Ticketscloud» на телефоне и компьютере и убедиться, что открываются нужные даты.
2. **Репозиторий GitHub.** Аккаунт GitHub к проекту не подключён, поэтому файлы пока лежат в общей папке проекта. Подключите GitHub ([Connect GitHub](https://claude.ai/connect-github)) и создайте пустой репозиторий, и я загружу туда сайт. Или загрузите содержимое папки сами (см. README).
3. **Ближайшие игры:** даты, время, цены, темы вечеров и ID событий в Ticketscloud (или скажите, что все даты продаются только через мета-событие).
4. **Афиши** (горизонтальные 4:3) и **фото/видео** с игр.
5. **Контакты организатора:** телефон, Telegram, e-mail — то, что можно публиковать.
6. **Форма заявок:** выбрать сервис приёма заявок (лучше с хранением данных в РФ) и подготовить политику обработки персональных данных. До этого форма предлагает написать в VK.
7. **Правила игры.** Ответы в FAQ «Как проходит игра» и «Можно ли прийти одному» написаны осторожно, без придуманных правил. Пришлите точные правила (размер команды, сколько раундов, призы), и я их уточню.
8. **Домен** (если будет свой) — после него нужно прописать полный адрес картинки превью `og:image`.

## 5. Что не удалось проверить

- Живое окно покупки Ticketscloud и реальные события в мета-событии (сеть закрыта).
- Виджет постов VK (подключён через официальный VK Open API, включается `vk.showPostsWidget` в `site.json`; vk.com из этой среды тоже недоступен). Если не загрузится, остаётся ссылка на сообщество.
- Референсы: главная WOW QUIZ и страница wowloto.ru/schedule отдают расписание через скрипт, поэтому их карточки игр и фильтры я не увидел. Структуру взял из видимой части: первый экран с CTA, якорь на расписание, путь к записи.
- Публикация на GitHub Pages: сайт **не опубликован**, пока нет репозитория.
